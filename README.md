## 🚀 실행 및 빌드 방법

### 1. 패키지 설치

Node.js 20.9 이상이 필요합니다. 클라우드 환경에서는 기존 체크아웃을 사용합니다.

```bash
cd /workspace/nextbike-web
npm ci
```

### 2. 로컬 개발 서버 실행
```bash
npm run dev
```
브라우저에서 `http://localhost:3000` 접속

### 3. 정적 프로덕션 빌드 (SSG)
```bash
npm run build
```
빌드는 지역·기종·칼럼 페이지를 사전 생성합니다. 실제 표시 속도는 기기와 네트워크에 따라 달라집니다. 견적 API는 서버 런타임이 필요하므로 정적 파일만 배포해서는 작동하지 않습니다.

### 4. 검증

```bash
npm test
npm run build
npm run typecheck
```

테스트는 텔레그램 응답을 모의하며 실제 알림을 보내지 않습니다. 프로덕션 서버는 빌드 후 `npm start`로 실행합니다. 개발 서버와 빌드는 `.next`를 공유하므로 동시에 실행하지 마세요.

### 5. 견적 알림 설정

배포 환경에 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`를 안전하게 설정하세요. 로컬에서는 Git에서 제외되는 `.env.local`을 사용할 수 있습니다. 값은 커밋하거나 로그에 출력하지 마세요.

- 설정 누락은 HTTP 503, 전달 실패는 HTTP 502, 잘못된 신청은 HTTP 400으로 응답합니다.
- 텔레그램의 HTTP 응답과 JSON `ok: true`를 확인해야 접수 성공으로 표시합니다.
- 사진 전송만 실패하고 연락처·신청 내용 전달이 성공하면 `photosDelivered: false`를 반환하고 사진 재전송 경로를 안내합니다.
- 이 API에는 별도의 접수 데이터베이스가 없습니다. 성공은 알림 전달 확인을 뜻하며, 장기 보관·접수 이력 관리가 필요하면 별도 저장소를 연결해야 합니다.

### 6. 이미지·폰트 유지보수

배포에 필요한 WebP와 폰트 파일은 저장소에 포함돼 있어 일반 설치·빌드에서 외부 폰트 서버나 이미지 변환 도구가 필요하지 않습니다.

- 이미지 재생성: `python tools/optimize-images.py` (선택 도구: Pillow 필요)
- 폰트 재생성·검증: `python tools/vendor-pretendard.py` (고정된 공식 원본과 SHA-256 검증)
- Pretendard 라이선스·출처: `public/fonts/pretendard/`

### 7. 매입 사례와 순위 기록

실제 거래일이 확인되지 않은 사례에는 날짜나 ‘오늘 완료’를 자동 생성하지 않습니다. 거래일을 확인한 경우에만 `src/data/cases.ts`의 `date`에 기록하세요.

순위 도구의 새 결과는 가져온 초기 검색 응답에서 추출한 웹문서 카드 순서이며, 광고·지도 등을 합친 절대 순위가 아닙니다. 접속 오류·파싱 불가는 미노출과 구분합니다. 기존 기록 파일은 보존하지만 과거 방식으로 작성된 순위와 새 방식의 값을 직접 비교하면 안 됩니다. 합성 과거 순위 생성은 더 이상 실행하지 않습니다.
